# GA4 fix check, 2026-11-10

**Result: the fix passes 10 of 10 checks. Production, without the fix, still fails the same 2 checks.** The first run is in `2026-11-10-ga4.md`.

## The fix (`src/components/Analytics.astro`)

1. `book_click`: a tracked click that opens another page of this site in the same tab now goes into `sessionStorage`. The next page sends it after gtag starts. gtag sends other clicks at once, as before.
2. `booking_submitted` now sends `via` (`whatsapp`, `sms` or `copy`).

The check (`scripts/check-ga4.mjs`) changed in two ways:

- It judges `book_click` at the end of the session, after the browser leaves the last page. A click that opens a new page can go out in any later batch. The check also requires exactly one `book_click` hit.
- `SERVE_FROM=http://localhost:8788` keeps the production address in the browser, but takes each page from the local build. GA4 reports only from the production address, so this is the only way to run the check on code before it goes live.
