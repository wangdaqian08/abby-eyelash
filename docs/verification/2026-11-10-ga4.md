# GA4 on the live site — 2026-11-10

**Script:** `scripts/check-ga4.mjs` (`npm run check:ga4`; before a deploy `npm run build && DIST=1 npm run check:ga4`)
**Target:** https://www.abbyeyelashes.com, measurement ID G-ND8T7ZBSLR (`src/data/site.ts`)
**Environment:** macOS, Node 25.6.0, Playwright Chromium 156 headless, phone size 375×812 with touch, locale en-AU
**What it checks:** no request to Google before a cookie choice or after "Necessary only"; after "Accept all", gtag.js loads,
`page_view` carries the user property `style_variant` (A/B look), `book_click` carries `style_variant` and `lang`, and the
choice is remembered on the next page load. Live runs send real hits tagged `utm_source=site-check`.

## Result

| Run | Pages | Result |
|---|---|---|
| 1. Live, before the fix (07:18 UTC) | live site, commit 2936f72 | **11 passed, 2 failed**: the first `page_view` has no `style_variant` |
| 2. Experiment: gtag call order | test page, hits stopped | `set user_properties` before `gtag('js')` puts `up.style_variant` on the first `page_view`; nothing else does |
| 3. Local build with the fix (07:22 UTC) | `./dist` on the live address, hits stopped | **13 passed, 0 failed** |
| 4. Live, after the fix is deployed | — | **not run yet** (needs the fix merged and deployed) |

**Failure in run 1 (real bug, in the site):** gtag.js sends the first `page_view` as soon as it reads `gtag('js')`. The
site set the user property after that, so the look only rode on the visitor's next hit; a visitor who left after one page
had no look, which would skew the A/B test's visitors-per-look. Fix: `src/components/Analytics.astro` sets the user
property before `gtag('js')`. The `style_variant` parameter on `gtag('config')` was dropped: run 2 shows it never reached
any hit. `page_view` still carries no *event* parameter `style_variant` (no call order gave it one); A/B reports use the
user-scoped dimension for visitors and the event parameter on `book_click` / `booking_submitted` for conversions.

Also seen in run 1: Google now collects at `region1.analytics.google.com`; the script's first version filtered only
`google-analytics.com` and saw no hits. Fixed in the script before the run below.
