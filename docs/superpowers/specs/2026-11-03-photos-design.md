# 网站加入 Abby 的真实照片 —— 设计

日期：2026-11-03。状态：等待确认。

## 1. 为什么做

网站现在用的是 Unsplash 占位图（见 `docs/IMAGE-PLACEHOLDERS.md`），上线前必须换成 Abby 自己的作品。照片是客人决定留下来、决定预约的关键。

- **网站最想让客人做的事：预约睫毛。** 美甲也可以预约，但美甲照片的主要作用是证明“Abby 手艺好”，最终还是希望客人去约睫毛。
- **客人约睫毛前最常问的三件事：** 能坚持多久？过程中、做完后会不会不舒服？具体多少钱？照片直接回答的是“多少钱、做出来什么样”。另外两个问题由文字回答（常问问题区已有）。
- 所有照片都已征得客人同意，露脸的照片也可以用。

## 2. 目标、非目标、反目标

**目标**
- 客人在手机上一眼看到“这一款长什么样、多少钱”，并且一点就能预约这一款。
- 同一个区里的照片尺寸统一，排列整齐，不让人觉得乱。
- 指甲照片按颜色分组，同一组尽量用同一种拍摄角度。
- 不伤害 SEO/GEO：文字仍然是网页文字，每张图都有中英文 alt，页面速度目标不变（`docs/GEO-STRATEGY.md` #15：手机 LCP < 2.5s，Lighthouse ≥ 95）。

**非目标**
- 不做单独的作品集页面、筛选按钮或灯箱放大。
- 不改价目表的内容和预约流程本身。
- 不处理雾眉页（没有眉毛照片），也不处理首页“关于”区的 3 张图（应该放 Abby 本人或店里环境的照片，现有素材里没有）。这两处继续用占位图。

**反目标（即使“能用”也算失败）**
- 美甲区的按钮比预约睫毛的按钮还显眼。
- 照片上的价格和价目表对不上（`IMG_2473` 上印着 “$180”）。
- 页面因为照片变慢，或者图片加载时页面跳动。
- 照片被裁坏：水印被切一半、眼睛或指甲被切掉。

## 3. 素材

原图在 `~/Desktop/abby-eyelash/`（睫毛）和 `~/Desktop/abby-eyelash/nails/`（指甲和视频），不在仓库里。

- 睫毛 25 张，全部不同。文件名就是款式名，对应价目表项目。注意 `造型款.JPG` 和 `造型款.HEIC` 是**两张不同的照片**：JPG 是横拍的单眼造型款特写（有水印）；HEIC 是竖拍的整脸自拍（没有水印）。
- 指甲 22 张，全部竖拍，文件名只有编号。外加一段视频 `VID_20260817下午92540427.MP4`（1080×1920，7.8 秒，黄色小花法式）。
- **只有 `角蛋白-翘睫1`、`角蛋白-翘睫3` 是前后对比**（上 = 做之前，下 = 做之后，用户确认）。`角蛋白-翘睫2` 是单张成品。`造型款-漫画`、`造型款-眼线加浓+下睫毛`、`造型款+下睫毛` 虽然也是上下两格，但两格都是做完后的效果，不是前后对比，不能标“前 / 后”。
- 格式：大部分是 JPG；`IMG_9264.heic` 需要转换。注意按 EXIF 方向摆正。
- 除 `造型款.HEIC` 外都有 Abby 水印，保留。裁图时水印要么完整保留，要么整个裁掉，不能只剩半个。

## 4. 已决定的方案

### 4.1 首页“睫毛款式”区（新增）—— 用户选了样稿 A

- **位置**：首页“服务”区（`Services`）下面，“优惠”区（`Offers`）上面。
- **内容**：6 张卡片，对应可在线预约的 6 个睫毛项目。每张卡片有一张 4:3 实拍、项目名、价格、时长，还有“约这款 →”。
- **卡片和照片的对应：**

| 项目（`service/option`） | 照片 |
|---|---|
| `lash-extensions/classic-natural` 日式单根 · 自然 | `单根自然.jpg` |
| `lash-extensions/classic-full` 日式单根 · 浓密 | `单根浓+下睫毛.JPG` |
| `lash-extensions/hybrid-natural` 开花 / 轻盈 · 自然 | `轻盈-自然.jpg` |
| `lash-extensions/hybrid-full` 开花 / 轻盈 · 浓密 | `开花-浓密.JPG` |
| `lash-extensions/styled` 造型款 | `造型款-仙子.JPG` |
| `lash-lift/keratin-lift` 角蛋白翘睫 | `角蛋白-翘睫2.JPG` |

- **价格和时长**：从现有数据（`prices.csv` → `src/data/services.ts`，以及 `priceText` 等现有工具函数）读取，不在组件里写死。
- **“约这款”链接**：用预约页现有的直达链接，比如 `/book?service=lash-extensions&option=classic-natural`，中文页用 `/zh/book?...`。预约页已经支持这种链接（`booking-client.ts` 末尾的 “Deep link”）。沿用现有的 `data-track="book_click"`。
- **手机 2 列**，样稿见 `.superpowers/brainstorm/…/lash-layout-v2.html` 中的 A。

### 4.4 统一尺寸和 SEO/GEO 规则

- **比例**：睫毛 4:3；指甲 3:4；服务页图位沿用代码现有比例（见 4.3）。翘睫前后对比图是唯一的例外，保持原比例。
- **接近正方形的指甲照片**（`IMG_7334`、`IMG_9024`、`IMG_9264`、`IMG_9011`、`6E6C1734…`）裁成 3:4 时会切掉约四分之一宽度。规则：所有指甲必须完整保留。做不到的话，就和同一颜色组“看全部”里的另一张对调位置；还不行就只放进“看全部”。用在服务页 detail 位的 `IMG_9011` 如果裁不好，换成同组的 `IMG_2020`。
- **裁图要人工把关**：眼睛、指甲和水印都不能被切掉，`IMG_2473` 的 “$180” 必须裁掉。
- **图片处理**：照片走 `astro:assets` 的 `<Picture>`，输出 AVIF/WebP 多种宽度（和现在的 `Gallery.astro` 一样）。每张图写明宽高，避免页面跳动。只有首页大图和服务页 hero 立即加载，其余都懒加载。
- **alt**：每张图都写中英文 alt，描述款式和颜色，必要时带地名，例如“日式单根自然款嫁接睫毛效果，Burwood”。项目名、价格、款名都是网页文字，不做成图片。
- **JSON-LD** 只能反映页面上看得到的内容（`GEO-STRATEGY` #11），不新增评分类结构化数据。

## 5. 约束

- 遵守 `design-system/MASTER.md` 和 silk-ui 规则：背景分层、浅色边框、`tabular-nums` 数字、Grid 折叠、在“减少动态效果”下关闭动画。
- 先在 375px 宽度检查，再看桌面。
- 中英文两套页面（`/` 和 `/zh/`）结构相同。
- 不新增依赖。

## 6. 交给实现者决定的

- 裁图方式：用脚本（Astro 自带 sharp）加人工核对，还是手工裁；仓库里放原图还是放裁好、缩到合适尺寸的母版（建议后者，长边约 1600px，避免仓库膨胀）。
- 照片在 `src/assets/` 下的目录和文件命名（建议 ASCII，例如 `lash/classic-natural.jpg`、`nails/img-6920.jpg`）。
- `ServiceImage.astro` 现在读 `public/images/services/` 且不做优化（代码里有 `shortcut:` 注释说明拿到真图后再升级），是否借这次改成 `src/assets` + `<Picture>`。
- 桌面端列数（建议睫毛卡片 3 列，指甲每组 3 列不变），以及各区的具体间距。
- 造型款英文款名的译法。
- 视频文件放 `public/`，以及具体的压缩参数。
- 是否把 JSON-LD `businessNode` 的 `image` 换成新首页大图。
